# Implem.Pleasanter.UiThemesPreflight
## テーマ改善 動作確認モジュールのご案内 ― 事前確認のお願い

Pleasanter のテーマまわりを刷新する「テーマ改善」を予定しています。  
正式リリースの前に、**ユーザーがカスタマイズされている画面が刷新後も問題なく表示・動作するか**を、あらかじめご確認いただくための動作確認モジュールをご用意しました。

> **対象**：Pleasanter をご利用中で、サイトに独自の **スタイル（CSS）・スクリプト（JavaScript）・HTML** を登録されているユーザー／サイト管理者  
> **ベースバージョン**：Pleasanter 1.5.8.1  
> **モジュールバージョン**：Pleasanter 1.5.8.9  
> **動作確認モジュールの配布**：2026年9月末　／　**正式リリース予定**：2027年1月  
> **動作確認モジュールの入手**：本リポジトリの [Releases](https://github.com/Implem/Implem.Pleasanter.UiThemesPreflight/releases) からダウンロード

> [!CAUTION]
> ## ⚠️ 運用中の Pleasanter をアップデートしないでください
>
> 本モジュールは、正式リリース前に動作を確認していただくための一時的な特別版です。運用中の Pleasanter をアップデートしてしまうと、通常版のバージョンアップの際に再びアップデートすることになり動作確認ができなくなるほか、特別版から通常版へアップデートした場合の挙動は保証できず運用に影響するおそれがあります。
>
> そのため、必ず **運用環境とは別に、新規（別URL）で立ち上げて** ご確認ください。接続先のデータベースは、後述の「4. 確認・修正の手順」でご案内する方法A〜Cから選べます（運用中のデータベースをそのまま参照する方法もありますが、その場合は運用データに影響する可能性がある点をご理解のうえでご利用ください）。
>
> 次のマニュアルに沿って **手動で新規セットアップ** してください。

## 1. このモジュールについて

Pleasanter のテーマ機能の設計を大きく見直したアップデートです。  
UIの世代（レイアウト）とテーマ（配色）を分離し、新しいテーマカスタム機能やダークモードの指定に加え、ハイコントラストなど**アクセシビリティも強化**しています。

ただし今回の刷新では、画面内部の構造（HTMLの組み立て方やCSSのクラス名）も整理しています。そのため、**ユーザーが独自に追加されたスタイル・スクリプトの一部が、そのままでは効かなくなる／表示が崩れる**可能性があります。

本「動作確認モジュール」は、正式リリースの前にこうした影響を洗い出し、**あらかじめ確認・調整していただく**ためのものです。事前に備えておくことで、リリース後もスムーズに移行できます。

---

## 2. 事前確認が必要な理由

正式リリースでは、Pleasanter 標準の画面には自動的にテーマ改善が適用されます。標準機能はそのまま新しい表示へ切り替わるため、特別な作業は必要ありません。

注意が必要なのは、**独自に登録・追加したカスタムコード**です。これらは標準の刷新に自動では追従しません。対象は次のとおりです。

- サイトの **スタイル（CSS）**
- サイトの **スクリプト（JavaScript）**
- サイトの **HTML**
- 拡張スタイル、拡張スクリプト

今回の刷新では、画面内部の構造（HTMLの組み立て方やCSSのクラス名）も整理しています。カスタムコードがこの構造に依存していると、リリース後に **記録・期限付きテーブル・ダッシュボードなどで表示崩れやスクリプトエラー** が起きることがあります。

そのため、正式リリースを迎える前に、これらのカスタマイズが問題なく動くかをご確認いただくようお願いしています。確認と修正の具体的な進め方は、次章以降でご案内します。

## 3. 事前確認ツール：PleasanterUiLint

**PleasanterUiLint** は、「どのカスタムが、どこで影響を受けるか」を**手作業で探さなくても機械的に洗い出せる**ツールです。
動作確認モジュールとあわせて、**[PleasanterUiLint.zip](https://github.com/Implem/Implem.Pleasanter.UiThemesPreflight/releases/download/1.5.8.9/PleasanterUiLint.zip) で配布**します。

- 運用中の Pleasanter に登録された **スタイル・スクリプト・HTML** を読み込み、今回の刷新で**影響を受ける箇所を一覧で指摘**します。
    - HTML は、その中のクラス名・ID と、`<script>`・`<style>` の中身を調べます。
- 出力は次の3つです。
    - **レポート（HTML）**：影響箇所を重要度つきで一覧
    - **一覧（CSV）**：Pleasanterに取り込んで「移行タスク管理テーブル」としても使えます
    - **修正案**：機械的に直せそうな箇所の書き換え案（※ユーザーのデータには一切書き込みません／確認用のみ）
- 重要度は次の3段階で示します。

| 重要度 | 意味 |
| --- | --- |
| **BREAKING** | 必ず直す必要があります。参照しているクラス名・ID・API が刷新後に無くなります |
| **RISKY** | 念のため確認してください。標準のスタイルが変わった箇所や、画面の構造に依存した書き方をしている箇所です |
| **UNKNOWN** | 自動では判定できません。スクリプトの中で組み立てている部分などです。目視で確認してください |

### 必要な環境

| 必要なもの | 備考 |
| --- | --- |
| **Python 3.12 以上** | 追加のインストール（pip）は不要です |
| **git** | ― |
| **Pleasanter の公開リポジトリ** | [Implem.Pleasanter](https://github.com/Implem/Implem.Pleasanter) を clone してください。GitHub のアカウントは不要です |
| データベースのコマンド（`sqlcmd` / `psql` / `mysql`） | 運用中のデータベースから直接読み込む場合に必要です |

### 使い方

zip を展開したフォルダで、次のコマンドを実行します。
運用中の Pleasanter のフォルダを指定すると、現在のバージョンを自動で調べ、データベースからスタイル・スクリプト・HTML を読み込みます。
**データベースへの書き込みは一切行いません**（読み取りのみ）。

```bash
python tools/check.py --repo <公開リポジトリを clone したフォルダ> --pleasanter <運用中の Pleasanter のフォルダ>
```

結果は `output/findings/report.html`（レポート）と `output/findings/findings.csv`（一覧）に出力されます。
データベースに直接つなげない場合の方法など、詳しい使い方は zip に同梱の **README.md** をご確認ください。

### ご利用にあたって

- まずこのツールで**確実に影響が出る箇所を特定**し、そのうえで動作確認モジュールの画面で実際の見え方を確認する、という流れがおすすめです。
- **注意**：このツールは「確実に壊れる箇所」を先に洗い出すためのものです。**細かな見た目の崩れや、画面の構造（要素の入れ子）の変化までは検出できません**。検出が 0 件でも、影響がないとは限りません。必ず動作確認モジュールの画面での目視確認とあわせてご利用ください。

## 4. 確認・修正の手順

### 全体の流れ

```
1. 事前確認ツール「PleasanterUiLint」で影響箇所を洗い出す
        ↓
2. 動作確認モジュールで実際の画面を確認し、表示崩れ・スクリプトエラーを見つける
        ↓
3. 見つかった箇所のスタイル／スクリプト／HTMLを修正し、動作確認モジュールで直ったことを確認する
        ↓
4. 修正したスタイル／スクリプト／HTMLを、運用中のサイトに「ドラフト」で用意しておく（正式リリース後に切替）
```

修正は **ドラフト（下書き）機能** を使うと、**運用中の表示に影響を与えずに準備**しておけます。正式リリース後に切り替えるだけで済みます。  
（ドラフト機能：<https://pleasanter.org/ja/manual/managers-guide/manage-table/common/draft/>）

確認の環境は次の3通りから選べます。運用環境に影響を与えない **方法A・方法B を推奨** します。確認したいサイトが少なければ **方法A**、テナント共通のスタイル・スクリプトや拡張機能も含めて全体をまとめて確認するなら **方法B** が便利です。方法Cは運用中のデータベースへ直接つなぐため、特別な事情がある場合のみとしてください。

### 方法A：新しい環境で確認する（推奨）

運用中の環境に影響を与えず、確認したいサイトだけを手早く用意できます。

1. 動作確認モジュールのPleasanterを、**現在とは別のURL・別のデータベースで立ち上げます**。
    - 運用中の Pleasanter とは別に新たに構築します。
2. 運用中のPleasanterから、確認したいサイトを **サイトパッケージとしてエクスポート** します。
3. `2. でエクスポートしたサイトパッケージ` を動作確認モジュールに **インポート** します。
4. 動作確認モジュールで画面を確認し、表示崩れ・スクリプトエラーがあれば、スタイル／スクリプト／HTMLを修正します。
5. 直したコードを、運用中のサイトに **ドラフト** で登録しておきます。
6. 正式リリース後に切り替えます。

### 方法B：運用データのコピー（バックアップから復元したDB）で確認する（推奨）

運用中のデータベースのバックアップを別のデータベースへ復元（リストア）し、その複製データを動作確認モジュールから参照する方法です。運用環境には一切触れずに、実データ全体（全サイト・全テーマ設定）をまとめて確認できます。方法Aのようにサイトを個別にエクスポート／インポートする手間がなく、方法Cのように運用DBへ直接つなぐこともありません。

1. 運用中のデータベースのバックアップを取得します（すでに定期取得している場合は、それを利用できます）。
2. 動作確認モジュールのPleasanterを、運用中の Pleasanter とは別に新たに構築します。
3. `2. で構築したデータベース` に、1. のバックアップを**復元（リストア）**します。
4. 動作確認モジュールで各サイトの画面を確認し、表示崩れ・スクリプトエラーがあれば、スタイル／スクリプト／HTMLを修正します。
5. 直したコードを、運用中のサイトに **ドラフト** で登録しておきます。
6. 正式リリース後に切り替えます。

### 方法C：運用中のデータで確認する

動作確認モジュールから**運用中のデータベースを直接参照**して確認する方法です。手早く始められますが、運用データに直接つなぐため、**特別な事情がない限りは方法A・Bを推奨**します。

1. 動作確認モジュールのPleasanterを、運用中の Pleasanter とは別に新たに構築します。
2. `1. で構築した Pleasanter の Rds.json` を開き、接続先を運用中の Pleasanter のデータベースに変更してから、Pleasanter を再起動します。
3. 動作確認モジュールで運用中のデータを参照し、各サイトを確認します。
4. 表示崩れ・エラーがあれば、スタイル／スクリプト／HTMLを **ドラフト** で修正します。
5. 正式リリース後に切り替えます。

## 5. 確認のポイント

まずは **普段よく使う画面** から確認するのがおすすめです。

- 記録・期限付きテーブル
    - 一覧画面
    - 編集画面
- ダッシュボード

特に、**独自のスタイル・スクリプト・HTMLを入れている画面**は重点的にご確認ください。  
「ボタンの位置がずれる」「色や枠が当たらない」「独自の操作ボタンが動かない」といった症状が出た場合は、そのカスタムが影響を受けています。

> どのカスタムが影響するかは、**PleasanterUiLint のレポートで具体的に特定**できます。刷新で消えたり名前が変わったりしたクラス名・ID・API の一覧（カタログ）も、`output/catalog/` に出力されます。

## 6. 新しいテーマ・カスタマイズ機能

今回のアップデートで、テーマの選択・カスタマイズがより柔軟になりました。**個人設定／テナント設定の「外観」**から設定できます。

### できること

- **テーマの選択**：3つのグループから選べます。
    - **カスタム（色を選ぶ）**：お好きな色でテーマを作成
    - **プリセット**：8種類（セルリアン／サニー／グリーンティ／マンダリン／さくら餡／ミッドナイト／トワイライト／茄子紺）
    - **ハイコントラスト**：3種類（後述）
- **カラーモード**：ライト／ダーク／**自動（お使いの端末の設定に追従）**
- **カスタム色**：**メインカラー・サブカラー・背景色**を自由に指定

### ★ ハイコントラストモード（新機能）

視認性を高めた**ハイコントラストテーマ**を3種類、標準搭載しました。強いコントラストで文字や境界を見やすくし、**アクセシビリティ**に配慮した環境をワンクリックで実現できます。

| テーマ      | 配色                |
| ----------- | ------------------- |
| 黄 / 黒     | 黄色 × 黒（ダーク） |
| シアン / 黒 | 水色 × 黒（ダーク） |
| 紺 / 白     | 紺 × 白（ライト）   |

テーマを選ぶだけで全画面に適用され、個別のCSS調整は不要です。

## 8. 動作確認モジュールに関するお問い合わせ

本動作確認モジュールは、**正式リリースまでの確認用の特別版**です。

- 原則として、**致命的な不具合（起動できない・データが壊れる等）以外の修正は行いません**。
- 表示の崩れなど軽微な不具合は、**いただいたご指摘を確認のうえ、正式リリース版に反映**します。正式リリースの準備の都合上、反映をご希望の場合は **2026年12月中旬まで** にご連絡いただけると確実です。
